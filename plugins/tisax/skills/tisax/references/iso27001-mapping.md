# TISAX ↔ ISO 27001:2022 Mapping

## Overlap
~70–80% of ISA Information Security controls map to ISO 27001:2022 Annex A / ISMS clauses: policies, organization, HR security, physical security, access control, cryptography, operations security, supplier management, incident management, continuity. An ISO 27001-certified ISMS is the strongest possible TISAX starting point — reuse its policies, risk register, SoA evidence, and audit artifacts.

## What ISO 27001 does NOT give you
| TISAX-specific element | Why it matters |
|---|---|
| **Fixed maturity targets + cutback scoring** | No SoA-style tailoring; every applicable question must reach target maturity (3) — weak areas cannot be offset |
| **Prototype Protection module** | Physical prototype security has no ISO 27001 equivalent |
| **High/Very High additional requirements** | Layered requirements beyond ISO baseline expectations |
| **Labels + ENX exchange mechanics** | Assessment result sharing, temporary labels, 9-month corrective window, 3-year cycles |
| **OEM expectations** | Data-classification handling per OEM terms; de facto contractual mandate from VW, BMW, Mercedes-Benz, Audi and others |
| **Assessment vs certification** | TISAX yields labels on the ENX platform, not a certificate; no ISO-style surveillance audits, but full re-assessment every 3 years |

## Practical mapping workflow
1. Map existing ISO evidence to ISA control areas (ISA2027 ships updated ISO 27001:2022 and NIST CSF 2.0 mappings)
2. Gap-assess the unmapped ISA content: prototype module (if in objectives), additional High/Very-High requirements, availability objectives
3. Re-express evidence in maturity terms (0–5) — ISO "implemented" ≈ maturity 3 only when established, documented, and demonstrably operating
4. Keep one ISMS: run TISAX objectives as a scope extension, not a parallel programme
