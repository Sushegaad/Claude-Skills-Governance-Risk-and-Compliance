# System Security Plan — IA.L2-3.5.3 (Multifactor Authentication)

Note: IA.L2-3.5.3 is one of the seven CMMC practices designated "critical" — it can never remain open in a POA&M at certification time (self-assessment or, if reinstated, C3PAO), regardless of your SPRS score. The entry below describes only what is currently implemented; the gap on legacy CAD workstations is called out explicitly rather than glossed over, and is routed to a named POA&M item as required.

---

## SSP Entry

| Field | Content |
|---|---|
| **Practice ID** | IA.L2-3.5.3 |
| **Requirement Statement** | Use multifactor authentication (MFA) for local and network access to privileged accounts and for network access to non-privileged accounts. |
| **Implementation Description** | See below |
| **Responsible Roles** | ISSO / IT Security Manager; Identity & Access Management (IAM) Administrator; Network Administrator |
| **Associated Systems** | Microsoft 365 GCC High tenant (Entra ID); Duo Security MFA gateway (VPN); on-premises Active Directory domain (legacy CAD workstations) |
| **Evidence/Artifacts** | See below |

### Implementation Description

MFA is enforced through two independent mechanisms covering the organization's cloud and network-perimeter access paths:

1. **Microsoft 365 GCC High / Entra ID.** All user accounts — privileged and non-privileged — authenticating to Microsoft 365 GCC High services (Exchange Online, SharePoint/OneDrive, Teams, and any CUI-relevant applications hosted in the tenant) are required to complete MFA via Entra ID Conditional Access policy. This satisfies the practice for network access to all cloud-hosted resources, for both privileged and non-privileged accounts.

2. **Duo MFA for VPN.** Network access via the corporate VPN is gated by Duo MFA at the point of connection, for all users establishing a remote session into the corporate network — satisfying the practice's network-access requirement for the VPN entry point, again for both privileged and non-privileged accounts.

3. **Gap — on-premises Active Directory (legacy CAD workstations).** Legacy CAD workstations authenticate against the on-premises Active Directory domain via standard username/password logon. **MFA is not currently implemented for local or network logon to these workstations.** This is a partial implementation of the practice as a whole: the requirement is only fully met for account types and access paths that receive MFA (M365/Entra ID and VPN); it is **not met** for local AD logon on the CAD workstation fleet, and this gap is not papered over here. This is tracked as **POA&M-IA-3.5.3-01** (see POA&M Reference below) with a target remediation date to be set by the responsible ISSO.

Because this practice is on the critical-practices list, the on-prem AD gap must be fully closed — not merely POA&M-tracked indefinitely — before the organization can pursue certification of any kind (self-assessment affirmation or, if reinstated, a C3PAO assessment). Do not affirm this practice as MET in SPRS until the gap is closed.

### Evidence/Artifacts

- Entra ID Conditional Access policy export demonstrating MFA is required for all users (privileged and non-privileged) accessing Microsoft 365 GCC High resources
- Duo MFA policy configuration and enrollment report for VPN access, showing coverage across all VPN users
- Active Directory Group Policy / authentication logs for CAD workstation domain, documented specifically to demonstrate the absence of an MFA layer on this segment (supports honest gap disclosure rather than omission)
- POA&M-IA-3.5.3-01 remediation record (see below)

### POA&M Reference

| Field | Content |
|---|---|
| Practice ID | IA.L2-3.5.3 |
| Weakness Description | Legacy CAD workstations authenticate via on-premises Active Directory with no MFA layer for local or network logon |
| Remediation Options | (a) Deploy Duo (or equivalent) Windows Logon/RDP MFA integration to the on-prem AD domain covering CAD workstations; (b) require CAD workstation network access to route through the VPN + Duo MFA control point before AD authentication is permitted; (c) migrate CAD workstations to Entra ID hybrid join to bring them under existing Conditional Access MFA policy |
| Milestone(s) | To be defined by ISSO/IAM Administrator with target dates |
| Scheduled Completion | To be set — this practice is certification-critical and cannot remain open at assessment |
| Resources Required | IAM/network administrator time; Duo or equivalent MFA licensing for on-prem AD integration; testing window for CAD workstation compatibility |
| Status | Open |
| Evidence of Closure | Updated AD authentication logs / Conditional Access policy showing MFA enforced for CAD workstation logon; updated SSP entry moving this practice to fully MET |
